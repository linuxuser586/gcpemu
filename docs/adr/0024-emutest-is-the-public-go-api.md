# emutest is gcpemu's public Go API; its own tests reach internals through WithConfig and Internal

FR-CI-009 asks for a Go package that starts an Instance per test or per package and returns configured clients. Every other Go package in this module is under `internal/`, so `emutest` is the only one another module can import, and its exported identifiers are gcpemu's public Go API. They name no `internal/` type, with two exceptions: `WithConfig(func(*config.Config))` and `Instance.Internal() *instance.Instance`, both documented as for gcpemu's own tests, with no compatibility promise. Another module can call neither usefully, since it cannot name `config.Config` and `instance.Instance` is not importable. `Option` is a struct with no exported fields, so options are made only by `emutest`'s constructors. `Instance` embeds nothing and exposes only Service endpoints, environment variables, client options, the Storage and Pub/Sub clients, and `Close`.

gcpemu's own tests turn the emulator's internal knobs and inspect its internals far more than any user test will. Those tests use the same package as everyone else, so the public surface is the one gcpemu itself relies on most, and the two escape hatches keep its own tests from pushing internal knobs into the public API. The cost is that gcpemu's tests read `inst.Internal().Env…` and `emutest.WithConfig(func(c *config.Config) {…})`, which is longer than before. A knob that users need becomes a named option, such as `WithStrictProjects`, instead of a `WithConfig` call. Helpers that only inspect gcpemu's internals, such as the VM relay's, live in `internal/emutestx`, not in `emutest`.

## Considered options

- **A `gcpemu/testing` package, as the SRS first named it.** It was rejected because it clashes with the standard library's `testing`, which every test file imports too.
- **Option as `func(*config.Config)`, and Instance embedding `*instance.Instance`.** This was the package before #27. It was rejected because another module can write no option of its own, and the embedding promotes every internal field and method into the public API.
- **A separate internal test helper for gcpemu's own tests, keeping `emutest` free of internal types.** It was rejected because the two helpers would have to start Instances identically, and gcpemu's own tests would then no longer exercise the package users depend on.
