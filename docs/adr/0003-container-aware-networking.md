# In the OCI image, the Instance joins its own networks instead of relying on the host

Cloud SQL, GKE and Cloud NAT start Managed containers through the Docker socket. When the emulator runs in the OCI image with the host's socket mounted (Docker-outside-of-Docker, FR-CI-006), two host assumptions break. Managed containers reach the emulator through forwarders bound on the services network's gateway IP, which exists only in the host's network namespace. The emulator also reaches Managed containers through ports published on `127.0.0.1` and through container IPs on bridges it is not attached to.

We decided that an Instance running in a container finds its own container through the socket and connects itself to the services network and to every VPC subnetwork bridge. It listens on its own address there instead of the gateway IP, and dials container addresses instead of published host ports. Outside a container nothing changes. The emulator container needs only access to the socket (`--group-add` of its group), never privilege: Managed containers that must be privileged, such as GKE nodes, get it from the daemon.

We rejected requiring `--network host`. It would need no code, but it works reliably only on Linux, and an emulator on the host network cannot sit on a compose network beside the services that use it, nor run as a CI `services:` container. Keeping one way of starting the emulator for compose and CI was the point of the image. The cost of our choice is a second addressing path that every Service must go through, with self-discovery that can fail if the container cannot inspect itself.
