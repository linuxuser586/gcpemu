## Host attachment

The emulator now links the host with VPC networks in both directions, on Linux and on a VM runtime
(Docker Desktop, Colima, OrbStack, Podman machine) alike (ADR 0014). It's a development aid, not
modelled on GCP, so a process on the host can stand in for a pod. It replaces routing the Service
CIDR through a node and pointing EndpointSlices at the bridge's gateway IP with sudo, which didn't
work on a VM runtime.

### Outward: Kubernetes Services by name from the host

The emulator's DNS (`127.0.0.1:5353` by default) answers host queries for

- `<service>.<namespace>.svc.<cluster>.<location>.<project>.gke.internal`, always, and
- `<service>.<namespace>.svc.cluster.local`, while exactly one cluster has that Service.

The answer is a Loopback alias (`127.0.0.x`) that the Service keeps until it's deleted, also across
restarts of an Instance with a data dir. The emulator serves each of the Service's TCP ports
there, so `curl http://web.default.svc.cluster.local:8080` reaches a pod. Headless Services aren't
answered; ExternalName Services are answered with their CNAME.

Send the two domains to the emulator's DNS:

```sh
# macOS (run `sudo gcpemu loopback install` first): one file per domain
for d in svc.cluster.local gke.internal; do
  printf 'nameserver 127.0.0.1\nport 5353\n' | sudo tee /etc/resolver/$d
done
# Linux with systemd-resolved, on any non-loopback link, e.g. the docker0 bridge
sudo resolvectl dns docker0 127.0.0.1:5353 && sudo resolvectl domain docker0 '~svc.cluster.local' '~gke.internal'
```

Aliases come from the `127.0.0.2`–`127.0.0.254` pool that Cloud SQL instances and forwarding rules
also use. With no free alias, or on a Mac without loopback aliases, the DNS answers SERVFAIL.
`gcpemu status` lists the Services that hold aliases, and `gcpemu doctor` flags short-name
collisions, an exhausted pool and Services without an alias.

### Inward: VPC workloads reach Offered ports on the host

Offer a host port on a subnetwork, and its workloads reach it at the subnetwork's Host address,
forwarded to `127.0.0.1` on the host. The process only needs to listen on loopback.

```sh
gcpemu offer 8080 53/udp --subnetwork projects/my-project/regions/us-central1/subnetworks/default
# prints the Host address, e.g. 10.128.0.1: point an EndpointSlice at 10.128.0.1:8080
gcpemu host-address --subnetwork projects/my-project/regions/us-central1/subnetworks/default
gcpemu withdraw 8080 --subnetwork projects/my-project/regions/us-central1/subnetworks/default
```

On a VM runtime the VM relay holds the Host address. Where the host routes to the network (Linux),
it's the gateway IP and the emulator binds the Offered port there, so offering a port that a
process holds on `0.0.0.0` or `[::]` fails, naming that bind. Ports that aren't offered aren't
reachable. The Host address and the Offered ports survive restarts of an Instance with a data
dir; `gcpemu status` and the Web console's VPC network page list them. The admin API serves them
at `/_emu/v1/host/address`, `/_emu/v1/host/offers` and `/_emu/v1/host/services`.

Neither direction is available when the emulator runs in a container.

See "Kubernetes Services from the host" and "VPC workloads reaching the host" in the README.
