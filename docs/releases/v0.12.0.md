## Breaking: the registry moved to port 4561, and loopback listeners also take `[::1]`

On macOS, AirPlay Receiver listens on port 5000 on all interfaces, and it's on by default. macOS
let gcpemu bind `127.0.0.1:5000` beside it, so the Instance started, but a client that resolves
`localhost` to `::1`, such as Docker Desktop's `docker push localhost:5000/...`, reached AirPlay
and timed out. Two changes fix this:

- **The Artifact Registry port is now 4561.** Push and pull with `localhost:4561/...` or
  `127.0.0.1:4561/...`. `gcpemu env` (`GCPEMU_REGISTRY`), `endpoints.json` and the console's pull
  and push commands give the new port. To keep the old port, start with `--port ar=5000`. A
  Persistent Instance needs no other change: on start its GKE nodes and Build agent pull from the
  new port.
- **With `--bind 127.0.0.1` or `localhost` (the default), every listener on that address also
  listens on `[::1]` at the same port**: the API gateway, GCS, Pub/Sub, the registry, DNS over
  TCP, the metadata server and the Google front end. Service endpoints still report the
  `127.0.0.1` address. A host without IPv6 loopback runs IPv4-only, as before. But if another
  process holds `[::1]:<port>` itself, the Instance now doesn't start, and the error names the
  port and IPv6. To fix it, free the port, or move that listener with `--port NAME=...`.

`gcpemu doctor` now checks each port on `127.0.0.1` and `[::1]`, and warns when another process
still answers on a port it could bind: that process holds the port on all interfaces. On macOS,
for ports 5000 and 7000, the warning tells you how to turn off AirPlay Receiver (System Settings
→ General → AirDrop & Handoff).

## GKE clusters serve the resource metrics API

Every emulated GKE cluster now runs k3s's bundled metrics-server and serves
`metrics.k8s.io/v1beta1`, as GKE does. `kubectl top nodes` and `kubectl top pods` work, and HPAs
on CPU or memory utilization scale instead of reporting `FailedGetResourceMetric`. Private
clusters get it too: its image is preloaded on every node. There is no setting to turn it off,
as on GKE. It runs as k3s ships it (Deployment `kube-system/metrics-server`), not under GKE's
`metrics-server-v<version>` name.

Existing clusters don't need to be recreated: a Persistent Instance installs metrics-server in each
cluster the next time it starts.
