## Changed: a backend service's custom request headers replace the client's

A backend service's `customRequestHeaders` now replace every copy of their names that the request
already carries, whether the client sent it or a URL map header action added it (#1233). Before,
they were added beside those copies, so a client could send its own `X-Client-Region` and the
backend saw both. Two entries with the same name both still arrive. `customResponseHeaders` are
unchanged: they are still added beside the backend's copy.

A backend that read a client's copy of a header the load balancer also sets now sees only the load
balancer's, as on GCP.

## Changed: Product images refreshed to GCP's November 2026 versions

The emulator now runs the versions GCP serves as of November 2026 (#895). The runbook for these
refreshes is [docs/product-images.md](../product-images.md).

- **Cloud SQL:** PostgreSQL 14.24, 15.19, 16.15 and 17.11. PostgreSQL 18.6 is unchanged.
  `maintenanceVersion` now ends in `.R20261013.02_04`. An existing instance moves to the new minor
  version the next time its container is created, and its `databaseInstalledVersion` and
  `maintenanceVersion` then report it. The refresh counts as maintenance already applied
  (ADR 0084).
- **GKE:** 1.37.2-gke.100 is added. The release channel defaults change to match GKE:

  | Channel | v0.16.0 | v0.17.0 | Offers |
  |---|---|---|---|
  | Rapid | 1.37.1 | 1.37.1 | 1.37, 1.36, 1.35 |
  | Regular (and no channel) | 1.36.5 | **1.36.4** | 1.37, 1.36, 1.35 |
  | Stable | 1.35.9 | **1.35.8** | 1.36, 1.35 |
  | Extended | 1.35.9 | **1.36.4** | 1.37, 1.36, 1.35 |

  The Regular and Stable defaults move **down** one patch, as GKE's did. A new cluster that names
  no version gets the new default. Existing clusters keep their version, since none is retired in
  this release. A test that expected `1.36.5-gke.100` for a cluster created without a version
  needs updating.
- **Add-ons:** Managed Service for Prometheus v0.17.2 and the Secrets Store CSI driver v1.6.2.
- **Managed emulators:** Firestore, Datastore and Bigtable run google-cloud-cli 594.0.1. The
  Spanner emulator is unchanged. Firestore and Datastore data saved by v0.16.0 loads unchanged.

## Changed: DNS forwarding follows the host's nameservers and falls back to a public one

Names outside every Cloud DNS zone are forwarded to the host's nameservers as before, but (#1196,
ADR 0089):

- A change to the host's `resolv.conf` (a VPN, a network change) takes effect without a restart.
  Before, it was read once at start.
- A nameserver that doesn't answer is skipped for 30 seconds, and the forwarding no longer waits
  2 seconds on each dead nameserver in turn.
- When none of the host's nameservers answer, the query goes to `8.8.8.8`, unless the Instance runs
  with `--offline`. With `--dns-no-forward`, nothing is forwarded, as before.

`gcpemu doctor` gains a DNS forwarding check that names the host's nameservers when forwarding
fails, and `/_emu/v1/dns/forwarding` reports them.

## Changed: Pub/Sub refuses Avro messages that declare huge maps or arrays

Avro `BINARY` validation, on publish and in `ValidateMessage`, now refuses a message whose map or
array declares more items than a message can carry, with `INVALID_ARGUMENT` (#1199). Before, a
small message that declared 2^40 items was accepted, or ran the emulator out of memory. A `bytes`
or `string` field may now be up to 10 MB, the publish limit. Before, more than 1 MiB was refused.

## A GKE cluster's DNS endpoint

A cluster created or updated with `controlPlaneEndpointsConfig.dnsEndpointConfig` now reports a
DNS endpoint, `gke-<hash>-<project number>.<location>.gke.goog`, and serves it to host clients
(#1229, ADR 0091). `gcloud container clusters get-credentials --dns-endpoint` and `kubectl` then
work against it, with IAM's `container.clusters.connect` checked on each request. To use it:

- Run `gcpemu dns install --suffix gke.goog`. It isn't a default resolver route, since once it is
  routed, real GKE DNS endpoints stop resolving on that machine.
- Run `gcpemu ca install`. gcloud writes no CA into a DNS endpoint kubeconfig.
- On Linux, allow port 443: `sysctl net.ipv4.ip_unprivileged_port_start=443`. `gcpemu doctor` says
  so when it's needed.

`container.clusters.connect` is added to `roles/container.clusterViewer`, `roles/container.viewer`
and `roles/viewer`, as on GCP. See "A cluster's DNS endpoint" in the README.

Changing a cluster's control plane endpoints with `UpdateCluster` now works in place. Before, it
returned `UNIMPLEMENTED`. `ipEndpointsConfig.enabled` and `enablePublicEndpoint` now read back what
was set, instead of always `true`, so OpenTofu no longer plans a change to them on every run. A
cluster created without an external address still can't turn on its public endpoint.

## GKE nodes keep free space on the runtime's disk

All of an Instance's GKE nodes keep their images on the container runtime's one disk, and each
node only collected images when its own boot disk filled. Five nodes could fill Docker Desktop's
disk before any of them collected (#1227). Now, when the runtime's disk has less than 10 GiB free,
the least recently used images that no node needs are removed across all clusters until 15 GiB is
free. Images in use, pinned or preloaded are never removed. Set the floor with
`gkeImageGcFreeSpace`, `--gke-image-gc-free-space` or `GCPEMU_GKE_IMAGE_GC_FREE_SPACE`, and turn it
off with `0`.

## Other fixes

- The binaries and images are built with Go 1.27.4, which fixes a crash an HTTP/1 client could
  cause in the server (GO-2026-6859, CVE-2026-97054). v0.16.0 was built with Go 1.27.3 (#1198).
- setup-gcpemu no longer ships `unzip-stream` and the 98 packages it pulled in, one of which
  declared no licence (#1202). setup-gcpemu only uploads artifacts, so nothing it does changes.
