## Changed: Cloud Storage refuses uploads outside their allowed size

- An XML API `PUT` with `x-goog-content-length-range: MIN,MAX` whose body is outside that inclusive
  range now fails with `400 EntityTooLarge` or `400 EntityTooSmall` (#1175). This applies whether
  the request is signed, uses an HMAC `Authorization` header, or is unsigned. Before, the object was
  stored and the request got `200`. A malformed header is ignored. So is the header on copies and on
  resumable or multipart part uploads.
- A POST policy upload outside the policy's `content-length-range` is now refused before anything is
  stored (#1185). Before, the object was stored and then removed again. In a versioned bucket, that
  cleanup also deleted the live version. A file that is too small now gets `EntityTooSmall`, as in
  Cloud Storage. Before, it got `EntityTooLarge`.

Clients that sent a range their own uploads broke now get the `400` that Cloud Storage returns.

## Changed: a GKE cluster on a Retired version is moved off it when brought up

When an Instance starts, or restores a State snapshot, a control plane or node pool on a Retired
version (one the emulator no longer ships) is upgraded before the cluster comes up (#1166,
ADR 0085). Before, such a cluster went to `ERROR` with `unknown version`. The control plane moves to
the newest patch of the oldest supported minor above its version. It never moves down. Each node
pool moves the same way, but never past the control plane. `autoUpgrade: false` and maintenance
exclusions don't prevent the move. The move is recorded as `DONE` `UPGRADE_MASTER` and
`UPGRADE_NODES` Operations and logged as a warning. The moved pools' nodes are recreated on the new
image.

No version is retired in this release, so no cluster moves yet. A later release that drops GKE
versions (#895) will move clusters on them.

## Changed: host clients reach GKE pods from the Host address

A connection from the host to a cluster Service at its Loopback alias now reaches the pod from the
subnetwork's Host address (#1177, ADR 0088). A policy that admits the host, such as Istio
`remoteIpBlocks: [<Host address>/32]` or a NetworkPolicy `ipBlock`, now matches it. Before, the pod
saw a node or bridge address. The emulator picks the endpoint itself (ready endpoints first, then
serving terminating ones, with `ClientIP` session affinity), so `internalTrafficPolicy` and topology
hints don't apply to host clients.

A node whose kernel can't send from the Host address still connects, from its own address.
`gcpemu doctor` warns about such nodes. Nodes created by an earlier release keep working through the
ClusterIP until they are recreated.

## Changed: `gcpemu reset` also resets the clock and empties the kubeconfigs

- `gcpemu reset` now sets the Emulator clock back to its base: real time, or a Deterministic
  Instance's own clock (#1172, ADR 0087). A test suite that advanced the clock and expected it to
  stay ahead after a reset will see it go back.
- A Reset, and so a State snapshot restore, now empties the Admin kubeconfig and the LAN kubeconfig
  (#1170). Before, they still listed the destroyed clusters. After a restore, they fill again as the
  restored clusters come up.

## Changed: `gcpemu ca install` replaces the Instance's earlier CAs

On macOS (System keychain) and Windows (user Root store), `ca install` now removes earlier roots
with the same Instance name before it adds the current CA (#1174). These roots are left behind by a
wiped data directory or a CA rotation. `ca uninstall` removes all of them. The plan lists each
delete before it asks for confirmation. On Windows, each delete adds a confirmation dialog. Roots of
other Instances are never touched. The match is on the exact name, so `x` doesn't match `x2`.
Firefox and Chrome NSS databases on Linux get the same cleanup.

## `gcpemu time show` and `gcpemu time reset`

`gcpemu time show` prints the Emulator clock and its offset without moving it. `gcpemu time reset`
sets the clock back to its base (#1172, ADR 0087). It never goes earlier than the base. Setting the
clock back only moves it. Deletions, expiries and retention that an advance set off stay done. Use a
State snapshot restore to undo them. `/_emu/v1/time` gains `GET` and `POST /reset`, and the
`/advance` response gains `offset`.

## Other fixes

- `gcpemu status` marks Resolver routes that are gone from the host's resolver, and says how to fix
  them (#1176). `status --json` gains `resolverRoutes.missing`.
- A Google-managed certificate is served before it reads `ACTIVE`, so a client that connects as soon
  as it reads `ACTIVE` no longer gets `tls: internal error` (#1184).
- `gcpemu env`'s help says `KUBECONFIG` doesn't promise that a cluster runs (#1168, ADR 0086).
- When a left-behind `endpoints.json` names a port held by a server that speaks first, such as
  `sshd`, `gcpemu start` and `ca rotate` now go ahead every time. Before, they sometimes refused
  and asked for the file to be removed (#1162).
